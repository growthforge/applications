MCP server · Copilot Studio · cost plans

An MCP server for cost-plan checks, designed for Copilot Studio

Three read-only tools a Copilot Studio agent can call to take a first pass over a cost plan. Every figure comes back with its basis, its status and its history, and nothing the tools do can approve a number.

  • Read-only tools, plain schemasNo approve, edit or send tools. No $ref, no exclusive bounds, no type arrays, string enums, checked on what the server emits; plans go in by reference.
  • Provenance in every resultBasis, status and history in the structured result, and in the words the model reads.
  • Tested with more than one clientThe SDK v2 client in current and legacy modes, the v1 SDK client, raw JSON-RPC with curl, and the MCP Inspector.

How it plugs in

From a question in Teams to an answer a cost manager can trace

  1. AgentCopilot StudioGenerative orchestration on; SharePoint method notes as knowledge, numbers only from tools.
  2. ProtocolMCP over Streamable HTTPOne stateless POST /mcp; a token for testing, Entra ID for production.
  3. ToolsThis serverCheck a plan, rebase a rate, a synthetic benchmark. Read-only.
  4. DataIndices and plansONS output price indices; synthetic benchmarks and plans. A firm's own index plugs in as a file.
  5. AnswerWith provenance, then reviewBasis, status and history in words. A named cost manager approves, outside the agent.

Security boundary: tools read bundled data and make no network calls; Host, Origin, rate limit and token are checked before a request body is read; approval stays with a person.
