# Partner quality check and quarterly review

> **Illustrative.** A sample template written for an independent job application. Not Vodafone material; not produced, reviewed or endorsed by Vodafone. It names no agreed terms and scores no partner: every term is a proposal to be agreed with each partner, and the check is a tool, not a verdict on anyone’s material.

Companion page: https://growthforge.github.io/applications/vodafone-ai-pathway/ (section “How this scales”).

## How the pieces fit

1. **Before anything goes live:** every curated or bought item passes the seven-question content quality check below. The questions are to be agreed with partners, so both sides know the standard before a contract is signed or renewed.
2. **Terms in writing:** each partner has a short register entry: what they supply, the terms agreed and who owns the relationship.
3. **Every quarter:** a review against those terms, using the pathway’s own data (module checks, use at work, open fixes). The review ends in one decision per partner: keep, adapt, replace or renew.

## The content quality check (seven questions)

Score each criterion Meets, Partly or Does not, and note the evidence. An item goes live only with no “Does not” on Role relevance, Accessibility or Currency.

| Criterion | The question | Score | Evidence |
|---|---|---|---|
| Role relevance | Is it built around a real task for this role, or is it a feature tour? | | |
| Practice | Does the learner do the task, with feedback? | | |
| Assessment | Does it test decisions or tasks, or only recall? | | |
| Accessibility | Captions, transcripts, keyboard use, no timed questions (WCAG 2.2 AA) | | |
| Localisation | Global English source, swappable examples, an in-market review | | |
| Currency | Are feature names and screenshots dated, with a named owner for updates? | | |
| Service levels | Are update turnaround and fixes written into the agreement and reviewed each quarter? | | |

## Example service levels (illustrative, to be agreed)

Starting points for the written terms, so the quarterly review has something to measure. Each is a proposal, not an agreed figure.

| Severity | What it covers | Example fix time | Example notice |
|---|---|---|---|
| 1 | Wrong or unsafe guidance (for example, advice that would breach the data rule), or content a learner cannot use with a keyboard or screen reader | Within 2 working days; the item is withdrawn until fixed | Partner tells the Specialist the same day it learns of the issue |
| 2 | Out-of-date feature names, screenshots or steps that still lead to the right result | Within 10 working days | 30 days’ notice of planned content changes |
| 3 | Typos, styling, minor wording | At the next scheduled update | Listed in the quarterly review |

## Quarterly review agenda (45 minutes per partner)

1. **What the learners did:** for each module that uses the partner’s content, the module check facility and the share who used it at work that week (from `metric-dictionary.csv`).
2. **What the partner did:** fixes and updates against the agreed times; open accessibility issues; changes to features or content since the last review.
3. **Quality check, re-run:** any criterion that moved from Meets to Partly or Does not since go-live.
4. **Decision:** keep, adapt, replace or renew, with the reason in one sentence. Renewal rests on use and usefulness, never on seats or completions.
5. **Actions:** owner and date for each.

## How a review feeds renewal

- A module below the item bank’s review line (a check facility under 0.4), or the least used at work, is adapted first; if the partner’s content is the cause and the fix is outside the agreed terms, the item is replaced at the next window.
- Seats licensed and completions are recorded for operations only. They are never the reason to renew.
- A partner that misses an agreed fix time twice in a quarter moves to monthly review until the backlog is clear.
