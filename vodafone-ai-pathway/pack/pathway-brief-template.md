# Pathway brief template (one page, signed before anything is built)

> **Illustrative.** A sample template written for an independent job application. Not Vodafone material; not produced, reviewed or endorsed by Vodafone.

Every role-based AI pathway starts as this one-page brief. The Skill Lead and the Learning and Performance Business Partner sign it before any content is designed, curated or bought. The fields are the same for every role, so pathways stay comparable across roles and markets. A filled example: `pathway-brief-account-managers.md`.

## Header

| Field | Fill in |
|---|---|
| Role | [the job family or role, in the business’s own words] |
| Pilot market | [one market, or “to be agreed”] |
| Brief version and date | [version], [date] |
| Pathway length | [weeks], chosen so the transfer measure can be read with data that already exists |

## The seven fields

| Field (the same for every role) | What to write | Guidance |
|---|---|---|
| Role and real tasks | Three or four frequent tasks the role does every week | Pick tasks that can be checked against a source (notes, a contract, a record). Avoid “use Copilot” as a task. |
| Data rule | What data the tasks touch, and where it may and may not go | Write it in plain words, with the approved tools named. A data protection colleague co-signs this line. |
| The check | The one verification habit every module teaches | One sentence the learner can apply to any output, for example “every commitment traced to the notes or the contract”. |
| Escalate | The decisions the learner does not own | Name them (for example price, contract terms, where data is held, security) and who owns each. The rule for every module: fix what your notes can put right; escalate what only someone else can decide. Open questions are routed to their owner the same day, whatever happens to the draft. |
| Team leaders | What team leaders do, and when | Model it, set the standard for “checked”, protect a short weekly practice slot, confirm the work sample. |
| Who owns what | One line per owner | Skill Lead: tasks, standard, stage checks. Learning and Performance Business Partner: market, cohort, team-leader time, local examples. Specialist: design, curation, partners, quality check, report. The teams that own usage reporting and HR data: the job-function data. |
| Signed | Names and date | Skill Lead; Learning and Performance Business Partner; date. |

## Questions to ask before drafting

1. Which three writing tasks take the most time each week?
2. Which mistake would cost most with a customer?
3. What data does the role touch, and where may it go?
4. Who signs off a commitment, a price or a data answer?
5. What already exists for this role: library content, existing labs or cohorts, vendor academies?
6. Which team leaders will give the practice slot fifteen minutes a week?

## Measures (four terms, agreed in the brief)

| Term | Evidence | What it cannot show |
|---|---|---|
| Experience (learner reaction: did it help with the job?) | | |
| Quality (capability growth: can they make the call?) | | |
| Learning transfer (AI adoption: is it a weekly habit?) | | |
| Business impact (productivity: did the work get better?) | | |

Never reported as impact: completions, logins, licences, satisfaction on its own, or self-reported minutes added together. See `metric-dictionary.csv` for definitions.

## Content quality check (curated and partner content)

A tool, not a verdict on anyone’s material. Agreed with partners before content goes live. The partner register and the quarterly review agenda that use it: `partner-quality-check.md`. Score each criterion Meets, Partly or Does not, and note the evidence.

| Criterion | The question | Score | Evidence |
|---|---|---|---|
| Role relevance | Is it built around a real task for this role, or is it a feature tour? | | |
| Practice | Does the learner do the task, with feedback? | | |
| Assessment | Does it test decisions or tasks, or only recall? | | |
| Accessibility | Captions, transcripts, keyboard use, no timed questions (WCAG 2.2 AA) | | |
| Localisation | Global English source, swappable examples, an in-market review | | |
| Currency | Are feature names and screenshots dated, with a named owner for updates? | | |
| Service levels | Are update turnaround and fixes written into the agreement and reviewed each quarter? | | |

## Choosing the next role and market

A role is ready for its own brief when all five hold:

1. Frequent tasks that can be checked against a source.
2. A real data or commitment risk the check can teach.
3. A Skill Lead and a Partner ready to own it.
4. Reporting is possible: job-function data loaded, and groups large enough to show (usage dashboards hide small groups).
5. The tool supports the market’s language for the task.
